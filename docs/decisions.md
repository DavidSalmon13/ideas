# Decisions

Choices made where the docs didn't settle the question. Newest last.

- **2026-09-23 — Minimal API in the foundation step.** Phase 0's acceptance ("`docker compose up` starts API") needs something to run, so the repo step ships a FastAPI app with only `GET /health` (`opp.api.app`). Real routes come in their phases.
- **2026-09-23 — Compose binds to localhost.** `127.0.0.1:8000` only, per plan.md §18 (no auth in MVP, localhost bind by default).
- **2026-09-23 — Ruff skips Markdown.** Ruff would reformat the Python snippets inside `plan.md`; the design docs are excluded from linting/formatting.
- **2026-09-23 — Python pinned to 3.12.x** (`>=3.12,<3.13`) to match plan.md §2 and the Docker base image.
- **2026-09-23 — Alembic baseline is empty.** Revision `0001` creates no tables; plan.md §24 puts the domain tables in Phase 1, which will add them as `0002`. The baseline just proves `alembic upgrade head` runs.
- **2026-09-23 — Settings use the `OPP_` prefix.** e.g. `OPP_DATABASE_URL`, `OPP_LOG_LEVEL`. Only settings used today exist; provider keys, budgets and model routing are added in the steps that need them.
- **2026-09-23 — Default database is `./data/opp.db`.** The `data/` folder is git-ignored and mounted as the Docker volume, so backups are "copy that file" (plan.md §29). The container runs `alembic upgrade head` on start.
- **2026-09-23 — Logs redact secret-looking fields.** Any log field whose name contains key/secret/token/password is written as `***` (plan.md §18, §31).
- **2026-09-23 — "Offline" CI is enforced in the tests.** A `tests/conftest.py` fixture blocks every non-loopback network connection, so a test that forgets a fake or cassette fails instead of quietly calling a real API. Installing dependencies in CI still uses the network.
- **2026-09-23 — CI also smoke-tests Docker Compose.** A second job runs `docker compose up --build` and waits for `/health`, covering the Phase 0 acceptance check that can't run in the dev container.
- **2026-09-23 — `unknown` is a fourth claim type.** specs.md lists `fact | estimate | assumption` for claims but also requires economics values tagged `verified | estimated | assumed | unknown`, and intent.md treats "could not verify" as a first-class answer. `Claim.type` therefore allows `unknown`, and `Claim.value_status` maps the four types to the four tags.
- **2026-09-23 — `None` vs. `unknown` in an Opportunity.** A claim-typed field is `None` until the stage that fills it runs; a stage that looked and found nothing records an `unknown` claim. This keeps "not researched yet" separate from "could not determine".
- **2026-09-23 — Unsourced facts are allowed by the model.** The auto-demote rule belongs to the Evidence validator (next Phase 1 step), so `Claim` accepts a `fact` with no sources rather than rejecting it.
- **2026-09-23 — Claims point to sources by id.** `Claim.source_ids` holds Source ids (specs.md §8.1 "Source refs"); Sources are stored once and shared.
- **2026-09-23 — Ranges on claims.** `Claim` has optional `value_low`/`value_high` next to `value`, because specs.md §14 asks for "ranges over points when uncertain".
- **2026-09-23 — Rules enforced in the models.** Blank `confidence_reason` is rejected; dimension scores are 1-5 and unique; any override (hard gate or fatal flaw) requires a `kill` verdict; a stage allows at most one kickback; a report halted at a stage must be marked incomplete. `HALTED_*` runs are not terminal because they can be resumed.
- **2026-09-23 — Not modelled yet.** `Profile` (gates/weights) is config and comes with the profiles work; `stage_state` lives in the Stage/AgentRun records rather than on the Opportunity. The default profile id is `bootstrap`.
- **2026-09-23 — DB tables store aggregates as a JSON document plus projected columns.** Each row keeps the whole Pydantic object in a `data` JSON column (the source of truth on read) alongside a few real columns that exist only to power the plan.md §5 indexes/filters (status, verdict, dedup_hash, …). Repositories always derive the projected columns from the domain object on write, so the two can't drift. This keeps Pydantic the single boundary (plan.md §31) without hand-writing a column per field of the deeply nested Opportunity. The queryable `claims`/`sources`/`claim_sources` tables are a secondary evidence index; the Evidence Store step wires the extraction into them.
- **2026-09-23 — Foreign keys are `DEFERRABLE INITIALLY DEFERRED`.** The document store uses no ORM `relationship()`s, so SQLAlchemy can't order inserts by FK; a parent and its children written in one transaction would otherwise fail the mid-statement check. Deferring the check to COMMIT makes intra-transaction insert order irrelevant while still enforcing referential integrity (verified: a dangling ref is rejected at commit). Portable to Postgres, which supports the same clause.
- **2026-09-23 — Repositories don't commit; the caller owns the transaction.** Matches the incremental per-sub-task persistence in plan.md §5/§7. A generic `DocRepository` gives `add`/`upsert`/`get` for standalone aggregates; child records (Claim, Evaluation, Experiment) extend a read-only base and take their owner id on a custom `add`, since the domain objects are reused across owners and don't carry one.
- **2026-09-23 — Source `url_hash` is a plain digest for now.** `sources.url_hash` (the dedup key) is `sha256(url)`; URL canonicalisation (stripping tracking params, normalising host/scheme) and the semantic lead/opportunity dedup arrive with the Evidence Store step. The `dedup_index` table and a thin `DedupRepository` exist now (it's a table) but hold externally-computed hashes only.
- **2026-09-23 — Canonical URLs for source dedup.** `url_hash` now hashes a canonical URL: `http`→`https`, lowercase host without `www.`, default port/fragment/trailing slash dropped, `utm_*` and common click-ids (`gclid`, `fbclid`, …) removed, remaining query params sorted. It lives in `opp.evidence.dedup` (pure, no DB imports) so the DB layer can use it without an import cycle; `opp.db.repositories.url_hash` re-exports it.
- **2026-09-23 — "Semantic hash" = sorted content words, no embeddings.** A lead's fingerprint is `sha256(version | shape | customer words | pain words)` after lowercasing, dropping stopwords and folding simple plurals. Why-now and title are left out (same customer + pain + shape is the same opportunity). Looser rewordings are caught by a token-overlap similarity (both customer and pain ≥ 0.6, same shape) against the run's own leads; cross-run checks use the exact hash in `dedup_index`. Embeddings would add an API call and cost for little gain at MVP scale.
- **2026-09-23 — "Merged (strongest evidence wins)" = keep one, kill the other.** Near-duplicates aren't combined field by field; the lead with the higher evidence score (source credibility tiers + claim confidence; ties keep the earlier lead) survives and the other gets status `duplicate` plus a `Kill` with `failed_gate=duplicate`.
- **2026-09-23 — Save and index are separate.** `EvidenceStore.save_lead` validates and stores; `index_lead`/`index_opportunity` write to `dedup_index` only when the caller (triage, the operator's discard) decides the item's fate. An opportunity is indexed under its own fingerprint *and* its lead's, so discarding it also blocks that lead from coming back.
- **2026-09-23 — Validator rules beyond the obvious.** A source ref that doesn't resolve to a stored Source is dropped (a fact needs a *retrievable* source). A quantitative fact backed only by low-tier sources becomes an `estimate` (specs.md §7.2). Sources are independent when their publisher differs, or their host when there's no publisher. Conflicts are made two-way and conflicted claims are capped at `medium` (a cap rather than "one level lower", so the pass is idempotent; Synthesis may lower further). Every change is noted on the claim's `notes`.
- **2026-09-23 — Assumption load.** Share of a section's claims that are `assumption`, `unknown` or `low` confidence; every claim in a section counts as decision-critical until profiles define which ones feed gates/weights. A section is flagged above 0.5. Opportunity sections: problem, customer, market, competition, why_now, business_model, economics, small_team_feasibility.
- **2026-09-23 — Staleness is not checked yet.** specs.md §26.6 leaves the threshold open and Refresh is V1, so the validator doesn't flag stale claims for now.
- **2026-09-24 — Tavily is the default search adapter.** plan.md §2 lists Tavily/Brave/Exa; Tavily is first, returns content snippets (what snippet-first discovery needs) and has a flat per-call price. It's called over plain httpx (moved from dev to runtime deps) rather than a vendor SDK. Price per call is a setting (`OPP_SEARCH_COST_PER_CALL_USD`, default $0.008 for a basic search) because vendor pricing changes.
- **2026-09-24 — Search metering is a wrapper, not the provider's job.** Providers report `cost_usd`/`latency_ms` on each response; `MeteredSearch` (bound to a run/stage/agent) turns every call, including failures, into a `Trace` via an injected sink. The sink will be the trace repository once the runtime exists; keeping it a callable avoids giving the research layer a DB dependency.
- **2026-09-24 — Search failures raise `SearchError` after bounded retries.** Timeouts, connection errors, 429 and 5xx are retried (default 2 retries, exponential backoff from 1s, honouring a numeric `Retry-After` up to 30s); 4xx and malformed responses fail at once. Callers degrade to `unknown` (plan.md §17). Results with a non-http(s) URL or empty snippet are dropped because they can't back a claim; unparseable publish dates become `None`.
- **2026-09-24 — Search caching comes with the next step.** plan.md §17 caches search results and pages together in SQLite; that ships with the Fetcher/cache item rather than here.
- **2026-09-24 — A `FakeSearchProvider` lives in `src/`.** Agent tests in later phases need an offline provider, so it's importable from `opp.research.fake` rather than hidden in `tests/`.
- **2026-09-24 — Fetcher pins the vetted IP.** plan.md §18 says "DNS-resolve-then-check". To make that sound against DNS rebinding, the Fetcher resolves the host itself, requires *every* address to be globally routable (IPv4-mapped IPv6 unwrapped; CGNAT, link-local/metadata, multicast, reserved all refused), then connects to that IP with the original `Host` header and TLS `sni_hostname` (which Python's ssl also uses for certificate checks). Redirects are followed by hand (max 5) and each hop is re-checked. Keep-alive reuse is off so a TLS session verified for one hostname never carries another's request. Environment proxies are ignored (`trust_env=False`) because a proxy would do its own DNS. Tested with a mock transport only; the first live run should confirm https against a real site.
- **2026-09-24 — Fetcher limits.** Ports 80/443/8080/8443 only; no credentials in URLs; text content types only (HTML, XHTML, XML, plain text), so PDFs are out for now; bodies are streamed and capped at 2 MB (truncated, flagged `truncated`), and an oversize `Content-Length` is refused up front; 15s total timeout. All of these are settings except the port and type lists.
- **2026-09-24 — Extraction with trafilatura, pure and offline.** `extract()` runs trafilatura's main-content extraction with metadata (title, date, site name, author); plain text passes through. Extracted text is still untrusted and must only reach prompts inside DATA blocks (plan.md §15).
- **2026-09-24 — Static credibility rules; unknowns are low and flagged.** `classify()` uses domain and path rules (government suffixes → regulatory/high; known research firms → industry_report/high; major press → trade_press/medium; review sites, job boards → medium; forums, social, blog hosts → low; `/pricing` → pricing_page/high; docs/help → vendor/medium). Anything else is `other`/`low` with `confident=False`, ready for the LLM tie-break that specs.md §26.4 recommends once the LLM gateway exists. Low is the safe default because a low-tier source can't carry a quantitative fact alone.
- **2026-09-24 — Source fields.** A Source keeps the URL as given (after redirects), not the canonical form, since forcing https could break http-only sites; dedup uses the canonical hash. Excerpts are whitespace-collapsed and capped at 500 characters.
- **2026-09-24 — Cache: SQLite tables, own sessions, free hits.** `search_cache` (key = provider + normalised query + k + freshness) and `page_cache` (key = canonical-URL hash) hold JSON with an expiry; defaults are 7 days for searches and 30 days for pages (settings). The cache wrappers keep the provider/fetcher interfaces, commit in their own short sessions (the cache is shared across runs, outside any run's transaction), never cache failures, and return cached search responses with `cost_usd=0`, so reuse still shows up in traces as a free call. DB calls are synchronous inside async code; that's fine for one user on SQLite.
